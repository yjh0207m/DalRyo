# 커뮤니티 수정 — 2026-11-03

기준: `chan`에 `origin/main`의 `26c4015`를 fast-forward 반영한 뒤 수정.

## 반영 내용

- 기존 게시물도 현재 공개 프로필 사진·닉네임을 표시한다. 본인 프로필은 소유자 문서 구독 하나를 공유해 변경/삭제를 즉시 반영한다. 다른 작성자는 공개 DTO를 최대 30명씩 묶어서 조회하며 피드 재조회·화면 재진입·앱 복귀 시 갱신한다. 오프라인에서는 저장된 게시물 정보를 유지한다.
- `socialAction.publicProfiles`: 인증된 사용자만 최대 30개의 유효 UID 조회 가능. 중복 UID를 제거하고 삭제된 사용자는 제외한다. 기존 공개 정보 화이트리스트만 반환하며 Firestore 읽기 권한은 넓히지 않았다.
- DM은 키보드가 열린 뒤 목록 높이가 바뀌거나 전송 결과가 늦게 도착해도 최신 메시지로 스크롤한다. 과거 대화를 직접 스크롤할 때는 위치를 유지한다. 전송 중에도 입력창을 유지해 키보드가 닫히지 않고, 전송 도중 작성한 다음 초안을 지우지 않는다.
- 새 대화는 검색 전 팔로잉 목록(30명씩 더 보기)을 보여 준다. 검색하면 검색 결과로 대체하고, 검색어를 지우면 팔로잉 목록으로 복귀한다. 검색/페이지 응답의 순서 역전을 방지한다.
- 본인/상대 프로필 모두 최근 러닝과 게시물에 목록·2열 그리드 전환을 제공한다. 그리드 게시물을 누르면 상세로 이동한다. 사진 없는 게시물은 러닝 아이콘과 거리로 표시한다. 기존 대표 색상을 유지한다.

## 검증

- 전체 Jest: 62개 스위트, 535개 테스트 통과. 이후 전송 중 다음 초안 보존 테스트를 추가했고 변경된 ChatScreen/PostCard/usePostAuthor 26개 테스트 통과.
- TypeScript·변경 파일 ESLint·Functions 빌드 통과.
- Firebase 에뮬레이터: 25개 서버 통합 시나리오 통과. 최신 사진/사진 삭제/중복 UID/잘못된 입력/개인정보 비노출 포함.
- Android Pixel_4_XL, 360×800dp: 긴 대화 26건에서 키보드 열기 및 전송 후 최신 말풍선 노출, 전송 후 키보드 유지, 프로필 러닝/게시물 그리드 전환, 검색 전 팔로잉 목록을 직접 확인했다. 가상 데이터만 사용했고 실제 메시지는 전송하지 않았다.
- `dalryo-dev`의 `socialAction` 배포 완료. 다른 함수·규칙은 배포하지 않았다.
- iOS용 동일 스크롤/레이아웃 처리는 테스트했으나 실제 iOS 빌드/기기 검증은 하지 않았다.
- 검증용 진입점과 가상 서비스 교체는 제거했다. 기존 `index.js`를 복원했다.

## 후속: 기존 DM의 프로필 사진

- 원인: 채팅방 생성 시 저장한 `conversations.profiles`의 사진을 대화 목록과 말풍선에서 계속 사용했다. 당시 사진이 없으면 나중에 프로필 사진을 등록해도 기존 방에는 반영되지 않았다. 메시지 작성 시점과는 무관하다.
- 대화 목록의 상대 아바타 및 대화창의 상대 프로필은 게시물과 같은 최신 공개 프로필 조회를 공유한다. 조회 중/오프라인에는 기존 방의 프로필을 사용하고, 최신 사진이 null이면 기본 아이콘을 표시한다. 새 메시지 전송이나 기존 대화 삭제가 필요 없다.
- 상대 UID가 아직 로드되지 않았을 때 빈 UID 조회를 하지 않으며, 대화 상대가 바뀔 때 이전 상대의 사진을 표시하지 않는다.
- 채팅/프로필 조회 테스트 24개, TypeScript 및 변경 파일 ESLint 통과. 서버는 기존에 배포한 `publicProfiles`를 사용하므로 추가 서버 배포는 필요 없다.
