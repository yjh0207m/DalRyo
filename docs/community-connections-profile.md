# 팔로우 목록·러너 프로필·DM 개선

2026-11-02.

## 사용 흐름

- 커뮤니티 헤더의 내 러너 프로필 → 팔로워/팔로잉 숫자 → 관계 목록.
- 관계 목록은 팔로잉/팔로워 탭을 제공하며 선택한 탭으로 돌아올 수 있다. 이름/프로필 영역은 상대 프로필, 메시지 아이콘은 해당 상대와의 DM으로 이동한다.
- DM 받은 편지함의 `팔로잉·팔로워에서 찾기` 버튼도 같은 목록으로 이동한다. 이름 검색은 계속 사용할 수 있다.
- DM 방의 상대 이름을 누르면 프로필로 이동한다.
- 상대 프로필: 이름·지역·관계 수, 팔로우/메시지 버튼, 펫 이름·종류에 맞는 성장 이미지·돌 상태, 누적 거리·러닝 횟수·최근 5회 날짜/거리/시간/페이스, 접근 가능한 게시물.

## 서버 데이터 범위

- 기존 `socialAction`의 `connections` 읽기 작업을 추가했다. `follows`의 실제 관계를 기준으로 30명씩 문서 ID 커서로 조회하며 삭제된 계정은 제외한다. 목록에는 기존 `publicUser`의 허용된 공개 필드만 반환한다.
- `profile` 응답에는 펫의 타입/성장 단계/이름/경험치/돌 상태와 러닝 요약을 추가했다. 사용자 본문·펫 본문·러닝 본문 전체를 반환하지 않는다.
- 이메일, 전화번호, FCM 토큰, 신체 정보, GPS 좌표/경로, 정확한 출발 시각, 내부 메모는 새 응답에 포함하지 않는다. 러닝 날짜는 한국 시간의 날짜 문자열이다.
- 기존 Firestore 비공개 사용자/캐릭터/러닝 문서의 직접 읽기 규칙을 넓히지 않았다. DB는 기존 `dalryo-dev` `(default)`, Standard 에디션이다. 새 컬렉션·인덱스·권한은 추가하지 않았다.

## DM 렌더링

- 역방향 FlatList를 제거했다. 서버의 내림차순 메시지를 화면에서는 시간 오름차순으로 배치해 오래된 메시지가 위, 최신 메시지가 아래에 온다. 첫 진입 시 텍스트를 뒤집는 transform에 의존하지 않는다.
- 이전 메시지 조회 버튼은 목록 위에 있고, 이전 기록을 볼 때는 새 메시지가 와도 강제로 최신 위치로 이동하지 않는다. 읽음 처리는 기존의 최신 메시지 로딩/하단 위치/포그라운드 조건을 유지한다.
- Android는 키보드 높이에서 시스템 창이 이미 줄어든 높이를 빼서 입력 영역 여백을 확보한다. iOS의 KeyboardAvoidingView는 유지한다. 전송 버튼과 입력창이 같은 영역에서 이동하며 키보드를 닫으면 여백을 원복한다.

## 검증

- 전체 Jest 49개 스위트, 302개 테스트 통과. 새 테스트는 프로필/DM 이동, 관계 탭 변경, 페이지 합치기·재시도, 펫·러닝 표시, 정상 메시지 방향·순서, 키보드 열림/닫힘을 포함한다.
- 로컬 Firebase Auth/Functions/Firestore 에뮬레이터 통합 시나리오 20개 통과. 32명 관계의 30+2 페이지, 중복 없는 결과, 팔로워 역방향 조회, 잘못된 종류·커서 거부, 펫·러닝 요약 및 비공개 필드 제외를 확인했다.
- TypeScript 및 Functions 빌드 통과. Android 360×800dp 에뮬레이터에서 임시 검수 진입점으로 실제 화면을 조작했다. 검수 데이터는 가상의 사용자·대화이며 실제 사용자에게 메시지를 전송하지 않았다.
- 실제 Firebase Storage의 오리 아기 이미지 표시와 러닝 요약 레이아웃을 확인했다. 임시 진입점은 APK 빌드 전에 제거하고 원본 index.js를 복원했다.
- iOS 실기기 키보드 및 화면은 Windows 환경에서 검증하지 않았다.
- 기존 `socialAction` 함수만 `dalryo-dev`에 배포 완료했다. Firestore 규칙과 다른 함수는 배포하지 않았다.
- Android release 빌드 및 APK 서명 검증을 통과했다. 소스맵에서 검수 진입점 미포함을 확인했다. 새 APK의 실제 계정으로 내 프로필과 팔로잉 목록 2명을 조회해 배포된 API 및 쿼리 동작을 확인했다.
