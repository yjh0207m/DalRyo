## 같이 달리기 방 (2026-10-27)

- (아래 '친구 요청 방식으로 변경'에서 코드 참가·공개 목록을 없앴다)
- 커뮤니티 → 같이 달리기: 방 만들기(이름·목표 거리·최대 인원), 코드로 참가, 대기 중인 방 목록, 나가기.
- 서버 함수 `roomAction`(asia-northeast3): list/create/join/start/leave/finish를 트랜잭션으로 처리한다.
  한 사람은 한 방에만 참가, 방장만 시작, 정원 초과·시작된 방 참가 차단, 방장이 나가면 남은 사람에게 위임, 모두 나가거나 완주하면 종료.
- 달리는 중에는 각자 거리·페이스를 `together_rooms/{id}/members/{uid}`에 올리고, 실시간 상위 3명 순위를 달리기 화면에 띄운다.
- 완주하면 일반 달리기와 같은 기록으로 저장(같은 세션 재시도 시 중복 저장 없음)한 뒤 방에 완주를 알린다.
- `dalryo-dev`에 함수·규칙·인덱스 배포 완료. 에뮬레이터 백엔드 통합 시나리오 11개 통과.
- ADB: 같이 달리기 화면 진입과 배포된 함수의 방 목록 조회 성공을 확인했다. 상태 표시줄 아이콘이 흰색으로 보이던 문제를 고쳤다.
- 실제 방 생성·두 기기 동시 달리기는 다른 사용자 목록에 노출되므로 실행하지 않았다(백엔드 테스트로 대체).

- 사용자 요청: 방 코드 입력 대신 친구 목록에서 같이 달리기를 요청한다.
- 친구 = 서로 팔로우한 사이. 같이 달리기 화면이 친구 목록이 되어, 친구를 골라 이름·목표 거리와 함께 요청을 보낸다.
- 친구 프로필(커뮤니티 → 러너 프로필)에 '같이 달리기 요청' 버튼: 그 친구를 골라 둔 채로 같이 달리기 화면을 연다.
- 받은 사람: 알림('같이 달리기 요청')과 같이 달리기 화면의 '받은 요청'에서 수락/거절. 알림을 누르면 같이 달리기 화면으로 간다. 푸시 설정이 켜져 있으면 푸시도 보낸다.
- 대기실: 응답 기다리는 친구 표시, 방장은 시작 전 '친구 더 부르기' 가능. 시작하면 응답 안 한 요청은 사라진다.
- 방 코드 입력·공개 방 목록 제거. 방과 참가자 기록은 방장과 요청받은 친구만 읽을 수 있다(규칙).
- 서버 `roomAction`: friends / invites / create(inviteUids) / invite / join(요청받은 사람만) / decline 추가, 기존 start/leave/finish 유지.
- 에뮬레이터 백엔드 시나리오 12개 통과 (친구 아닌 사람 요청 차단, 미초대자 참가·읽기 차단, 거절 시 자리 반환, 추가 초대, 시작 시 미응답 요청 정리 포함).
- 앱 테스트 116개, TypeScript, ESLint 통과.
- `dalryo-dev`에 roomAction·socialAction·규칙·인덱스 배포 완료. ADB에서 같이 달리기 화면이 친구 목록·받은 요청을 오류 없이 불러오는 것을 확인했다(테스트 계정은 서로 팔로우한 친구가 없어 빈 안내 표시).
- 두 계정으로 요청 → 수락 → 함께 달리기는 아직 실제로 해 보지 않았다(백엔드 테스트로만 검증). 이전 공개 방 목록용 인덱스 1개는 서버에 남아 있다(삭제하려면 --force).
- 에뮬레이터 실행 메모: firebase-tools는 Java 21 이상이 필요하다. Android Studio 내장 JBR(25)과
  `JAVA_TOOL_OPTIONS=-Djdk.net.unixdomain.tmpdir=C:/tmp/jdk`로
  `npx firebase emulators:exec --project demo-dalryo --only auth,functions,firestore "node scripts/test-social-functions.cjs"`를 실행한다.
